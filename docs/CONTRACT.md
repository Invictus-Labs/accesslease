# AccessLease shared technical contract (coordinator-owned)

Resolves the "proposed defaults" in PRD sections 6 and 8 so the three workers build one coherent product. The PRD wins on any conflict. Open questions are listed at the end; surface them to the coordinator, do not decide silently.

## 1. Stack and runtime
Node.js >=22.12 production runtime, TypeScript strict ESM (`module: nodenext`), Fastify 5 API + worker, `pg`, `zod`, PostgreSQL 17 (metadata store), React 19 + Vite lease view, Vitest, Playwright. Exact pinned versions are in `package.json`. The dev toolchain (jsdom) needs Node >=22.22.2 (24.15+, 26+); host Node 25 is unsupported. QA records the supported-runtime check on Docker `node:22` and on a supported host Node.
Reference implementation patterns (auth, sessions, CSRF, job leases, transactional outbox, composite workspace FKs, migrations, compose, verify script) exist in the public ScopeGuard repository: read them with `git -C "<workspace>/scopeguard" show main:<file>` (read-only; never its worktrees; copy patterns, add no dependency on it).

## 2. Providers (the heart of AC-03/04/05/07)
Interface lives in `src/connectors/provider.ts` (backend freezes it at M0). Two implementations:

- **`postgres-role` (REAL local provider; the only provider that can satisfy live criteria).** Target is a separate disposable PostgreSQL 17 cluster (never the metadata database). Native TTL: `CREATE ROLE ... LOGIN PASSWORD ... VALID UNTIL '<expires_at>'`; narrow scopes: `GRANT SELECT|INSERT|UPDATE ON <schema>.<table>` (grammar `pg:<schema>.<table>:<select|insert|update>`; no `ALL`, no `*`, no superuser/createrole/createdb/replication/bypassrls, no ownership, no DDL). Provider-native facts to document and TEST (the "chosen provider cache/session behavior"): `VALID UNTIL` is enforced at authentication only, so a session that already connected survives expiry until it is terminated. Revocation therefore = `pg_terminate_backend` on the role's sessions + `ALTER ROLE ... NOLOGIN` + `REVOKE` + `DROP ROLE` (order and failure handling are the backend's design), verified by (a) introspection (`pg_roles`, `pg_stat_activity`) AND (b) a denied-use probe (a real connection attempt with the issued credential must fail). The maximum residual-access window must be derived, documented in `docs/contracts/` and measured by a test: native TTL blocks new logins at `expires_at`; an already-open session can outlive `expires_at` until AccessLease revokes it (target: revocation requested within 30 s of expiry, verified result recorded).
- **`synthetic` (labelled SYNTHETIC; deterministic).** In-process fake with fault injection (timeout, outage, ambiguous issue, partial revoke, stale introspection). Used for the offline demo, deterministic state-machine/fault tests and the no-DB-cluster path. It reports `kind: "synthetic"` everywhere and can never produce live evidence.

Provider contract (shape, backend finalizes): `capabilities()` -> `{nativeTtl, revocation, introspection, deniedUseProbe, maxResidualAccessSeconds}`; `issue({leaseId, attempt, subject, resource, scopes, expiresAt})` -> `{providerRef, credential?}`; `lookup(providerRef)` -> `{state: present|absent|unknown, validUntil, activeSessions}`; `revoke(providerRef)`; `probeUse(providerRef)` -> `denied|allowed|unknown`. `issue` must be idempotent on `(leaseId, attempt-key)`: a retry identifies the same provider grant (deterministic role name derived from the lease), never a second grant (AC-03, AC-06). A provider without native TTL is refused (AC-03). Outbound endpoints come from admin config and are checked against an allowlist including redirects and DNS resolution; no private-address surprises.

## 3. State and uncertainty (PRD section 6, exactly)
`REQUESTED -> APPROVED -> ISSUING -> ACTIVE | ISSUE_UNKNOWN`; expiry/task closure/operator revocation -> `REVOKING -> REVOKED_VERIFIED | REVOCATION_UNCONFIRMED`. Elapsed time alone never produces `REVOKED_VERIFIED`; only independent verification does. `REVOCATION_UNCONFIRMED` carries `next_retry_at` and a visible warning and is never rendered green. `ISSUE_UNKNOWN` triggers reconciliation (lookup by deterministic provider ref), never a blind re-issue. Restart sweeps overdue leases before any new issuance. Add no states without telling the coordinator. History is append-only (`audit_events`, `revocation_attempts`).

## 4. API (all routes under `/api/v1`)
As in PRD section 6: `POST /leases`, `POST /leases/{id}/approve {plan_hash}`, `POST /leases/{id}/revoke {reason}`, `GET /leases/{id}`, plus list (cursor pagination, max 100), one-time credential retrieval `POST /leases/{id}/credential` (authenticated, scoped, never in URL/query/log/webhook/browser storage; consumed once), `GET /leases/{id}/evidence`, evidence export/import, task-closure `POST /leases/{id}/close`, auth (login/logout/session, CSRF), admin policy get/set, health (`/health/live`, `/health/ready`; failed migration stops readiness), events pull `GET /events?after=<cursor>`. Error body `{error:{code,message,request_id}}` with statuses 400/401/403/404/409/413/422/429/503 as specified. Cross-workspace object IDs return 404 with no state change. Mutations accept `Idempotency-Key` (scope workspace+actor+route, same key+body -> same receipt, changed body -> 409, retained >=7 days). `plan_hash` = SHA-256 of the canonical JSON (documented encoding, sorted keys, UTC ISO timestamps) of `{task_ref, subject_ref, resource_ref, scopes(sorted), expires_at, policy_hash}`; approval binds that hash and has its own expiry. Request/response JSON Schemas ship in `schemas/`.
Roles: admin (policies/connectors/bootstrap), operator (scoped workflows), viewer (redacted reads). Policy: default TTL 1 h, hard max 8 h, minimum TTL (default 60 s; tests may lower it through the admin policy), scope allowlist/denylist; only admins change policy. Sessions: revocable HttpOnly cookies + CSRF; no default password (bootstrap via CLI).

## 5. Persistence and data
Tables per PRD section 6 (`leases`, `approvals`, `provider_grants`, `revocation_attempts`, `audit_events`) plus what the build needs (workspaces, users, memberships, sessions, jobs/outbox, idempotency keys, policies). UUID primary IDs, UTC timestamps, `schema_version` on serialized documents, content hashes over documented canonical JSON, composite workspace FKs. Secrets (issued credentials, probe secrets, provider admin URL) encrypted with an operator-managed key (`ACCESSLEASE_SECRET_KEY`, outside the database); a retrieved credential is purged; probe secrets purge after verified revocation. Retention 90 days redacted evidence (configurable), primary deletion within 24 h, rotated backups expire within 30 days (documented defaults, operator approval required before real data; say so in the runbook). Expand/contract migrations; failed migration => not ready. Worker jobs: bounded leases, fenced completion, restart reclaims leased jobs without discarding uncertain external outcomes (AC-13).

## 6. Evidence bundle (AC-10)
Versioned (`schema_version`) export with canonical-JSON content hashes and a manifest; import into a clean installation re-verifies every hash and references; truncated, tampered or unsupported-version bundles fail with no partial accepted state (transactional import). Limits: 25 MB metadata, 1,000 files, 250 MB blob cap with explicit override; validate size/schema before processing; validate paths/symlinks/archive expansion. Bundles work offline.

## 7. Redaction and hostile input (AC-09)
Planted fake secret tokens (QA fixtures) never appear in logs, errors, exports or reports. Report/UI text is HTML-escaped; malicious HTML renders as text. Logs redact credentials, personal fields and authorization headers.

## 8. CLI (`accesslease`, package bin) and exit codes
Commands (surface builds, backend exposes the service functions): `serve`, `worker`, `migrate`, `bootstrap-admin` (no default password), `demo --out DIR` (synthetic provider, fixed clock, static report + evidence bundle, no network), `export`, `import`, `verify-bundle`, `report`, `doctor`, `events`. Exit codes: `0` ok; `1` runtime error; `2` invalid input / refused by policy; `3` dependency unavailable / disconnected live connector (explicit failure, AC-08); `4` unresolved uncertain state present (ISSUE_UNKNOWN or REVOCATION_UNCONFIRMED) so the result must not be read as success. Evidence directories default to owner-only permissions. Demo URLs use `localhost`; the default bind is `127.0.0.1` and docs explain `0.0.0.0` semantics.

## 9. Configuration (environment)
`ACCESSLEASE_DATABASE_URL`, `ACCESSLEASE_SECRET_KEY` (32 bytes, base64), `ACCESSLEASE_PUBLIC_URL`, `ACCESSLEASE_HOST` (default `127.0.0.1`), `ACCESSLEASE_PORT` (default `8791`), `ACCESSLEASE_PROVIDER` (`synthetic` | `postgres-role`), `ACCESSLEASE_PROVIDER_ADMIN_URL` (target cluster admin URL, only for `postgres-role`), `ACCESSLEASE_EGRESS_ALLOWLIST`, initial policy defaults (`ACCESSLEASE_TTL_DEFAULT_SECONDS=3600`, `ACCESSLEASE_TTL_MAX_SECONDS=28800`, `ACCESSLEASE_RETENTION_DAYS=90`). Telemetry is off and there is no telemetry code. Tests read `ACCESSLEASE_TEST_DATABASE_URL` and `ACCESSLEASE_TEST_PROVIDER_DATABASE_URL` (superuser URLs to disposable servers; each test file creates and drops its own uniquely named database/roles).

## 10. Ecosystem adapter boundary (optional, disabled by default)
Versioned envelope `{schema_version:1, event_id, source, resource_id, event_type, occurred_at, revision, evidence_ref, correlation_id?}`; at-least-once pull delivery; consumers dedupe `event_id`, reject unsupported major versions, keep ordering/version metadata and never infer current state from an old event. No raw credentials in events. No sibling product is a runtime dependency. Backend owns the outbox and `GET /events`; surface owns the reference consumer in `src/adapters/`.

## 11. UI (React lease view + static report)
Lease list and lease detail showing state, expiry, last_verified_at, revocation status, attempts and audit trail; `REVOCATION_UNCONFIRMED` and `ISSUE_UNKNOWN` use a warning style and text, never a green "revoked" state; loading, empty and failure states render. A static HTML report (`accesslease report`) with HTML escaping, readable tables and empty/error states. Browser tests drive the real UI against the real API (no route mocks).

## 12. Performance
Benchmark the deterministic core on 2 CPU/4 GB: 1,000 records within 30 s excluding provider I/O (QA records it as an experiment, not an SLA).

## 13. Open questions the coordinator tracks
Provider choice for pilots beyond the local sandbox, retention approval, and the human drill are operator decisions (PRD section 8/9). Everything in this document is a proposed default until the operator confirms; the first release is the synthetic + real-local-Postgres MVP.
